# 証跡撮影スキル(evidence-capture)

Web 画面の**修正前後**を、見る人が「どこを見ればよいか」「何がどう変わったか」をすぐ分かる形で撮る。
画面に帯・枠・吹き出しを**重ねて**撮り、スクショ・動画・比較画像を出力する。

| モード | 使う場面 | 出力 |
|--------|---------|------|
| **証跡取得モード** | 修正の動作確認。修正前後を同じ観点で撮って比べる | `{label}_{name}.png`(注釈付きスクショ)/ `{label}.webm`(動画)/ `{name}_compare_{比較名}.png`(比較画像) |
| **注釈モード** | 調査資料。**現状の**画面や CSV 出力に、枠線・吹き出しで説明を書き込む(比較しない) | `{label}_{name}.png` |

Playwright MCP は使わない(MCP では録画できず、MCP のブラウザは devicePixelRatio が 1 でないため切り抜きがずれることがある)。同梱スクリプトを node で実行する。

## 同梱スクリプト(`scripts/`)

以下 `<skill>` はこのスキルのディレクトリ(例: `.claude/skills/evidence-capture` または `~/.claude/skills/evidence-capture`)。

| スクリプト | 役割 |
|-----------|------|
| `capture.js <config.json>` | Chrome を headless 起動して CDP 接続し、(必要なら)ログイン → `pages[]` を順に開いて注釈付きスクショと動画を保存する。`read` に指定した要素の表示文字列を JSON で出力するので、期待値どおりかをここで判定する。設定項目はファイル冒頭のコメント参照 |
| `annotate.js` | 注釈を描くブラウザ側ヘルパー(capture.js が注入する)。注釈の書式はファイル冒頭のコメント参照 |
| `compose.js <config.json>` | 修正前・修正後のスクショを**左右に並べた比較画像**を作る |
| `csv2html.js <in.csv> <out.html> --mark G-P:red` | CSV を列記号付きの表 HTML にする。`--mark` の列範囲は `#mark-1`… の要素になり、注釈の target に使える(注釈モード) |
| `http2html.js <response.txt> <out.html> --request "GET /api/x"` | `curl -si` の応答とリクエストを 1 枚の HTML にする。JSON の各行は `[data-path="items.0.price"]` で注釈の target に使える。画面の無い API の修正前後を撮るときに使う(下の「画面の無い API の修正」) |
| `github-attach.js login` / `upload <PR URL> <file>...` | 画像・動画を GitHub の添付(user-attachments)としてアップロードし、PR 本文に貼る文字列を出力する。git にはコミットしない。webm は mp4 に変換して上げる(任意) |
| `video-sheet.js <動画.webm> <出力.png> [間隔秒] [列数]` | 録った動画を一定間隔で切り出し、時刻付きのコマを並べた一覧画像を作る。動画は Read ツールで読めないので、**録ったら必ずこれで中身を確かめる**(ステップE2 の 5) |
| `chrome.js` | 共通処理(Chrome の起動・接続、区間だけを録る録画)。Windows / macOS / Linux 対応 |

## 前提条件

- Node.js 18 以上、Google Chrome(場所が標準でなければ環境変数 `CHROME_PATH`)
- `playwright-core`: プロジェクトの依存にあればそれを使う。なければ `npx -y @playwright/mcp@latest --help` を一度実行して npx キャッシュに入れる(または `npm i -D playwright-core`)
- 録画用 ffmpeg: 初回に `capture.js` がエラーで導入コマンド(`node <playwright-core>/cli.js install ffmpeg`)を示すので、それを実行する
- **出力先・config.json はリポジトリの外の一時ディレクトリ**(Claude Code のセッション scratchpad など)に置く。証跡はコミットしない
- パスワードなどの秘密は config に書かず、`"${env:名前}"` で環境変数から渡す(ステップE2)
- ログインしないと見られない外部サイトの画面(GitHub の Actions のログなど)は、config の `"profile"` にログイン済みの Chrome のプロファイルを指定して撮る(`github-attach.js login` のプロファイルを使える)。CSP でインラインのスクリプトを禁じているサイトでも注釈を描けるよう、capture.js は CSP を無視して開く

## 見せ方(注釈の仕組み)

**動画は画面操作をそのまま録ったもの**にする(表紙・章カード・スライドのような演出や、修正前後をつないだ動画は作らない)。新しく足すのは、画面に重ねる下表の注釈だけ。

- **ログイン画面や読み込み中の白い画面は録らない**。capture.js は「画面の表示が終わってから次の画面へ移るまで」の区間だけを録ってつなぐ
- **何を確認しているかは最初のコマから表示する**。帯と枠・吹き出しを出してから録画を始め、枠を数回脈打たせて目を引く。1画面を見せる長さは config の `hold`(既定 4000ms)
- **枠・吹き出しの文字は、人が読み切れる長さだけ見せてから暗転する**。表示してすぐ暗転すると読めず、動画として失敗している。capture.js は吹き出しの文字数から読める長さ(1.5 秒 + 1 文字 100ms。最低 3 秒・最大 5 秒)を出し、`hold` がそれより短ければ延ばす(延ばしたことを標準エラーに出す)
  - 帯の一文は操作の間ずっと出ているので数えない。**長すぎても失敗**で、止まった画面が続くとフリーズして見える。読める長さを超えて見せ続ける設定(以前の `tail` など)は入れず、`hold` も 5 秒を超えて指定しない
  - **スクショを早いタイミングで撮りたいとき(「反映の約 1 秒後」の画面など)に `hold` を短くしない**。`shotAt`(枠・吹き出しを出してから何 ms 後に撮るか)で撮る時点だけを早める。撮った後も、動画は `hold` の残りだけ枠・吹き出しを見せ続ける
  - 修正前の事象が「数秒たってから変わる」ものなら、見せ続けている間に画面が変わる様子もそのまま映る。吹き出しは「反映の約 1 秒後も〇〇のまま。変わるのは 3〜4 秒後(期待値は反映と同時)」のように、変わる前と後のどちらを見ても矛盾しない書き方にする
- **動画は録画を止めた区間が詰まる**。`cut` だけでなく、スクショを撮る間(`shotAt` の時点)も録画を止めている。止めた区間は動画から消えるので、動画の中の経過時間は実際の時間と一致しない
- **「何秒で変わるか」そのものが修正の論点のときだけ**、画面右上のタイマーで実際の時間を測る(表示が遅れる・待ち時間が長い、などの修正)。
  それ以外の修正(表示内容・文言・件数など)では付けない。いつも付けるものではない
  - 反映などのボタンを押す `click` に `"timer": { "label": "反映から鍵が外れるまで", "until": { ... } }` を付けると、押す直前に始まり、
    画面が `until` の状態になった瞬間に止まって、その秒数を出し続ける。続けて `{ "waitTimer": {} }` で止まるのを待つ
  - 数え始めは、ページが実際にクリックを受け取った瞬間(Playwright はクリックの前にボタンが止まるのを待つので、その待ちは含めない)
  - 測った秒数は「押してから画面が変わるまで」で、ダイアログが閉じる・描き直すなどの時間も含む。修正後でも 0 秒にはならないので、
    吹き出しは「反映と同時に」ではなく「反映の直後に」のように書き、修正前との差で示す
  - 判定はページ内で描画のたびに行う。`until.state` は gone(消えた)/ present(出た)/ text / notText(その文字を含む・含まない)。
    画面から離れると描かれない一覧では、`whileVisible`(CSS セレクタ)で「その要素が画面に映っている間だけ判定する」にする
  - タイマーが動いている間は、capture.js は録画を止めない(cut もスクショもしない)。時間を測る区間はノーカットになる
  - **修正前と修正後の両方で、同じ操作・同じ条件のタイマーで測る**(片方だけ測っても比べられない)。吹き出しには秒数を書かず「右上のタイマーの秒数」と指す
  - 変わる場所が操作する場所から離れているときは、押す前に(ダイアログの後ろでも)`scrollTo` で変わる場所を画面に入れておく。押した後に画面を送ると、送る間の変化を見落とす
- **観点(ユースケース)が変わるところは切り替わりが分かるようにする**。画面(`pages[]` の1要素)ごとに、暗転から明けて帯がスライドインし、見せ終わったら暗転する。capture.js が自動で入れる
- **最初の画面は暗転させない**。動画の最初のコマがサムネイルになるため、枠・吹き出しのある画面から始める
- 該当画面で操作が必要な場合(検索・ボタン押下・入力など)は `actions` に書く。帯を出した状態で操作の様子を録り、操作が終わってから枠・吹き出しを出す
  - クリック・入力する箇所には**マウスカーソル**が動いて波紋が出る。入力は1文字ずつ打つ(capture.js が自動で出す)
  - ツールチップなど、マウスを重ねている間だけ出る表示は `{ "hover": "セレクタ" }` で重ねる。重ねたまま枠・吹き出しを描いて録る・撮る
  - 画面上の操作で別の画面へ移る様子を見せたいときは、その `pages[]` の `url` を省略し、移動先の表示を `{ "waitUrl": "..." }` / `{ "waitFor": "セレクタ" }` で待つ
  - URL を直接開くより、利用者が実際に行う操作で画面を移るほうが「何をしたか」が伝わる。操作で移れる画面は操作で移る
  - **画面の読み込みが終わるのを待っているだけの区間は、録画から切って詰める**。見せる必要がないため。その待ちを書いた操作に `"cut": true` を付けると、その操作の待ち(`wait` / `waitFor` / `waitText` / `waitUrl` など)の間だけ録画を止め、待つ前のコマと待った後のコマを**そのままつなぐ**(暗転・フェードアウト・フェードインは挟まない)。例: `{ "click": "text=\"在庫一覧\"", "waitText": "商品コード", "wait": 3000, "cut": true }`
    - クリックや入力そのもの(カーソルの動き・波紋)は切らずに見せる。切るのは、その後の待ちだけ
    - 操作の結果として画面が変わる様子を見せたい待ち(反映してから表示が変わるまで、など)には付けない。修正前後で「すぐ変わる/数秒かかる」が論点のときは特に付けない
    - 画面移動そのものを見せる必要がなければ、`pages[].url` で開いてもよい(`waitFor` と `settle` で表示を待つ間は録らない)。どういうデータを見ているかは `premise` で示す
- **幅で見た目が変わる画面は、幅の区切りごとに撮る**。プロジェクトが幅の区切り(ブレークポイント)を決めているなら、区切りの帯ごとに 1 つずつ幅を決め(例: 375・768・1024・1440px)、`viewport.width` だけを変えた設定ファイルを幅ごとに用意して、修正前・修正後をそれぞれ撮る。比較画像は幅ごとに作り、ファイル名と説明に幅を入れる(`<名前>_compare_768.png`、「768px」)。区切りの境目で出し方が変わる修正は、境目の両側(例: 599px と 600px)も撮る。1 つの幅だけでは、ほかの幅で崩れていないことを示せない
- **修正で変わるもの(出る・消える・変わる要素)が、変わる瞬間に画面(ビューポート)内に入っているようにする**。操作する場所と変わる場所が離れているときは、`viewport` の高さを広げて両方を 1 画面に入れる。画面外で起きた変化は動画に映らない
- **消えた要素は、消えた後の画面で「どこから消えたか」を示す**。消えた要素は注釈の対象にできないので、その位置に繰り上がった要素(次の項目の見出しなど)を囲み、「〇〇が消えた(△△の次が□□になった)」と書く。操作前の状態は `premise` で消える要素自体を囲んで見せる
- **しばらくすると自動で消える表示(スナックバー・トースト)**は、枠・吹き出しを描いてスクショを撮るまでの間に消えることがある(反映から描画まで 1〜3 秒かかる)。最後の操作を `{ "waitFor": "<その要素>" }, { "hover": "<その要素>" }` にして、マウスを重ねて自動で消えるのを止める(マウスを重ねたことは証跡の説明に書く)。止められない表示は `hold` を表示時間より短くする
- **動画の終わりは、最後の画面の枠・吹き出しを読める長さだけ見せて、そのまま終える**。capture.js は最後の画面を暗転させず、他の画面と同じ長さ(`hold`)で終える。それ以上の止まった画面は足さない

| 要素 | 内容 | 動画での出方 |
|------|------|------------|
| 帯 | 画面上部に「修正前(赤)/修正後(緑)」の札、見出し(`title`)、**何を見る画面かの一文(`caption`)** | 最初から表示。注釈・前提・操作する場所が帯に隠れるなら画面下端へ移す(下記) |
| スポットライト | 注釈の対象以外を暗くする | 最初から表示 |
| 番号付きの枠 | 対象の少し外側に角丸・影付きで描く(アプリ自身の入力エラー枠と見分けるため)。注釈が2件以上なら①②…を振る | 最初から表示し、録画の開始時に数回脈打つ |
| 吹き出し・矢印 | 枠と同じ番号・色で**短文** | 最初から表示 |
| 前提(`premise`) | どういう条件のデータかを、検索欄などに枠と「前提：…」の吹き出しで出す | 操作の最初から検索の間だけ。スクショには出ない |
| 暗転・スライドイン | 観点(画面)の切り替わりを示す | 各画面の始まりと終わり(最初の画面は暗転なし) |
| マウスカーソル・波紋 | `actions` のクリック・入力箇所を示す | 動画のみ |

スクショは全注釈がそろった最終状態を、帯を含めて切り抜く。

- **動画の帯は、見せる対象を隠さない端に置く**。ツールバーや右上のメニューなど画面最上部が対象の画面では、上端の帯がそれを覆ってしまう。capture.js は、帯を出した時点にある注釈・前提の対象と `actions` の操作する場所、描いた枠・吹き出し、カーソルを動かす先(クリックで後から開いたメニューの項目など)が上端の帯に重なると、帯を**画面下端へ移す**。下端へ移した画面では、その画面の間は上へ戻さない(帯が上下を行き来すると見づらいため)。タイマーは帯のすぐ内側に置く
  - 自動で決まる位置が合わないときは、config か `pages[]` に `"bannerPos": "top"` / `"bottom"` を書いて固定する(既定は `"auto"`)
  - 帯を移したことで画面下端の対象が隠れていないかは、ステップE2 の一覧画像で確かめる

### 文言の書き方

- `caption`(帯の一文)は**何を見る画面かだけ**を短く書く。修正前は「〜なのを修正したい」「〜になっている」、修正後は「〜になっていることを確認」。仕様の詳細や原因は書かない(それは PR・チケット本文に書く)
- **修正前は、期待値と、どう間違っているかを吹き出しに書く**(例:「期待値は0件だが、①〜③が表示されている」)。帯には書かない(帯は何を見る画面かの一文だけ)
- **前提条件は検索している間だけ出す**(`premise`)。常時は出さない(画面の情報量を増やさないため)
- **変更がないことを確かめるケース(影響しないはずのデータ)は、修正前の時点から「修正不要」と分かるようにする**。修正前の config でそのページに `"banner": { "text": "修正前・修正不要", "color": "green" }` を付け、`caption` を「修正不要：〇〇は期待値どおり（変更がないことを確認するケース）」、吹き出しを緑で「期待値どおり（修正不要）。〇〇」にする。compose.js の `compare[]` にも `"unchanged": true` を付ける
- **動画は全ケースとも検索から録る**。URL で結果画面を直接開かず、利用者が行う検索から `actions` で操作する(どういう条件のデータを見ているのかが分かるように)。読み込みを待つだけの区間は `"cut": true` で詰める(上記「見せ方」)
- 吹き出しは「どこが」「どうなっているか」を1行で。必要なら `<b>` で強調する
- 色: 赤=問題(修正前の事象)/ 緑=期待どおり(修正後・変化なし)/ 青=比較対象・参考 / 橙=注意 / 灰=補足
- 画面に出る番号(例: 注文番号)と URL の内部 ID が違うことが多い。帯の見出しには画面に出る番号を書き、報告では両方を併記する

## 証跡取得モード

修正前・修正後の**両方**を、**スクショ・動画・比較画像のすべて**で作って載せる。修正後の静止画だけで終えない。
修正前を撮る環境が用意できないときは、修正前を省かずにユーザーに確認する。

### ステップE1: 撮影対象の決定

1. 修正内容から確認すべき画面とデータを決める。原則2パターン撮る
   - **不具合が出るデータ**: 修正前は事象が出て、修正後は解消する
   - **影響しないはずのデータ**: 修正前後で表示が変わらない(デグレがないことの証跡)
2. **全ケースを撮る**。開発 DB に該当データがないケースは、SQL などでデータを作って修正前後で確認する(作成手順は報告・PR に載せる)
3. 注釈の対象(`annotate[].target`)と `read` のセレクタをソースから特定する。スクショの切り抜きに入れたい周辺(画面のヘッダー部など)は `clip` に書く
4. 修正前・修正後それぞれの `caption` と吹き出しの文言、検索から結果画面までの `actions`、検索中に出す `premise` を決める(上記「文言の書き方」)

### ステップE2: 撮影

1. アプリ(と API)が起動していることを確認する(例: `curl -sk -o /dev/null -w "%{http_code}" <baseUrl>`)
2. config.json を一時ディレクトリに作り、修正後(`"label": "after"`)を撮る。例:
   ```json
   {
     "label": "after", "baseUrl": "http://localhost:3000", "outDir": "<tmp>/evidence", "port": 9361,
     "login": {
       "url": "/login",
       "actions": [ { "fill": ["input[name=email]", "test@example.com"] }, { "fill": ["input[type=password]", "${env:APP_PASSWORD}"] },
                    { "click": "button[type=submit]" } ],
       "waitUrlNot": "/login"
     },
     "pages": [
       {
         "name": "out-of-stock", "url": "/items",
         "title": "在庫ゼロの商品（商品コード A-100）",
         "caption": "在庫が「0」と表示されることを確認",
         "premise": { "target": "input[name=q]", "note": "在庫が 0 件の商品" },
         "actions": [ { "fill": ["input[name=q]", "A-100"] }, { "click": "button.search" }, { "waitFor": "span.stock" } ],
         "read": ["span.stock"],
         "clip": ["main"],
         "annotate": [
           { "target": "span.stock", "color": "green", "note": "在庫：<b>「0」</b>と表示される", "pos": "right" }
         ]
       }
     ]
   }
   ```
   ```bash
   APP_PASSWORD='<テスト用パスワード>' node <skill>/scripts/capture.js <tmp>/evidence/after.json
   ```
   - **パスワードは config に直接書かない**。`fill` の値に `"${env:名前}"` と書くと、実行時に環境変数の値に置き換わる(未設定ならエラーで止まる)。値はプロジェクトのドキュメントやユーザーから受け取り、コマンドの環境変数で渡す
   - `ignoreHTTPSErrors`(既定 true)は開発サーバーの自己署名証明書を通すためのもの。localhost 以外(ステージングなど)を撮るときは `false` にする
3. 修正前(`"label": "before"`、port は修正後と別の番号、`caption`・吹き出しは修正前の文言)を撮る
   - フロントエンドの修正: 未コミットの変更がないことを確認してからベースブランチをチェックアウト → ホットリロードを待つ → 撮影 → **必ず作業ブランチに戻す**
   - バックエンドの修正: 再ビルド・再起動が必要になる。手順がプロジェクトのドキュメントから明らかでなければユーザーに確認する
4. 比較画像を作る。例:
   ```json
   {
     "outDir": "<tmp>/evidence", "port": 9390, "name": "ISSUE-123",
     "title": "ISSUE-123 商品一覧の在庫表示",
     "compare": [
       { "name": "out-of-stock", "title": "在庫ゼロの商品（商品コード A-100）",
         "before": "before_out-of-stock.png", "after": "after_out-of-stock.png",
         "point": "在庫：空欄 → 「0」" }
     ]
   }
   ```
   ```bash
   node <skill>/scripts/compose.js <tmp>/evidence/compose.json
   ```
5. 確認する
   - 出力 JSON の `read` が期待値どおりか(修正前は事象が出ている、修正後は解消している)
   - スクショと比較画像を **Read ツールで目視確認**する(枠の位置・吹き出しの重なり・文字の切れ・データの取り違え)。問題があれば config を直して撮り直す
   - **動画も中身を確かめる**。スクショが正しくても動画が正しいとは限らない(スクショは録画を止めた後に撮るため)。修正前・修正後の両方で一覧画像を作って Read ツールで見る:
     ```bash
     node <skill>/scripts/video-sheet.js <tmp>/evidence/after.webm <tmp>/evidence/after-sheet.png 1.5 5
     ```
     一覧画像で次をすべて確かめ、1 つでも外れたら config を直して撮り直す(気になるコマは
     `<ms-playwright>/ffmpeg-*/ffmpeg-<OS 名> -ss <秒> -i after.webm -frames:v 1 f.png` で原寸を書き出して見る)
     - **本題が映っている**: 修正で変わるもの(出る・消える要素、表示される文言)が、変わる前と後の両方のコマで画面内に見えている
     - **待ちが長くない**: 読み込み中の表示や同じ画面が何秒も続く区間がない(出力 JSON の `sameAsPrevious` が長く連続していない)
     - **注釈が正しい対象を指している**: 枠の中が空になっていない(自動で消える表示が、描いた後に消えていない)。前提の吹き出しが操作の後まで残って別の要素を指していない
     - **終わり方**: 最後のコマに最後の画面の枠・吹き出しが出ている(暗転や途中の画面で切れていない)
     - **読める長さ**: 各画面で、枠・吹き出しが出てから暗転するまで、吹き出しを読み切れる秒数(3〜5 秒)続いている。1〜2 コマで暗転していたら `hold` を短くしていないか確かめる(早く撮りたいなら `shotAt`)。逆に、注釈が出たまま 5 秒を超えて何も動かない区間(特に動画の最後)があれば長すぎる(5 秒でも見る人には十分長い)
     - **データ**: 動画の中の値(選んだ選択肢・表示件数など)が `read` の結果と合っている

### ステップE3: 証跡を載せる

貼り先と書式はプロジェクトの規則に従う。共通の方針:

- **比較画像を主役**にする。個別スクショは比較画像があれば省略してよい
- **動画は PR 本文に、再生できる形で載せる**。PR があれば `github-attach.js` で添付し、出力された `markdown` を本文に書く
  ```bash
  node <skill>/scripts/github-attach.js login                    # 初回だけ。開いた Chrome で GitHub にログイン(ユーザーの操作が必要)
  node <skill>/scripts/github-attach.js upload <PR の URL> <tmp>/evidence/ISSUE-123_compare_out-of-stock.png <tmp>/evidence/after.webm
  ```
  - webm は mp4(H.264)に変換してから上げる(webm のままだとプレイヤーにならない)。変換用 ffmpeg が無ければエラーに導入コマンドが出る
  - 動画の URL 行は前後を空行で囲み、独立した段落にする
- ケースごとに「何がどう変わったか」を1行で書く
- ファイル名は英数字にする(チケットシステムによっては日本語名の添付を本文から参照できない)

### 画面の無い API の修正

画面に出ない API(BE)の修正でも、修正前後のスクショ・動画・比較画像を作る。撮るのは「同じリクエストに対して応答がどう変わったか」。

1. 修正前と修正後の API を起動し、同じリクエストを `curl -si` で送って応答を保存する(`before.txt` / `after.txt`)。リクエストの本文があるときはファイルにして `--request-body` で渡す
2. `node <skill>/scripts/http2html.js before.txt <tmp>/before.html --request "POST /api/items" --request-body body.json --title "商品の登録"`(after も同じ)
3. capture.js の `pages[].url` に `file:///<tmp>/before.html` を書き、証跡取得モードと同じ手順で修正前・修正後を撮り、compose.js で並べる
   - 変わった項目を `"target": "[data-path=\"items.0.price\"]"` で囲み、修正前は赤で「期待値は〇〇だが △△ が返る」、修正後は緑で書く
   - ステータスが変わる修正は `#status` を囲む。リクエストも写るよう `"clip": ["#request", "#status", "#body"]` にする
4. 認証のヘッダー(Authorization・Cookie など)は http2html.js が伏せる。本文に個人情報・秘密が入る API は、テスト用のデータで撮る

## 注釈モード

**現状の**画面や出力ファイルを撮り、枠線・吹き出し・矢印で説明を書き込んだ画像を作る。修正前後の比較は行わない。config で `"video": false` にする。

### ステップA1: 撮るものと書き込む内容を決める

1. 説明したい内容を、画面で見せられる単位に分ける(1枚1メッセージ)
   - **現状の画面**: 不具合が見える画面、または原因になっている設定・マスタの画面
   - **操作の起点の画面**: ボタン押下後に何が起きるか(API・バッチ・判定ロジック)を吹き出しで説明する
   - **出力結果**: CSV・帳票は実際に出力し、`csv2html.js` で表にして、問題の列を色枠で示す
2. データは**読み取りだけ**で確認する。登録・更新・削除ボタンは押さない(CSV 出力などの読み取り操作は可)
3. 色の意味をそろえる: 赤=問題・削除対象 / 青=残す・修正対象 / 緑=期待値・正常 / 橙=注意・範囲外 / 灰=補足
4. 吹き出しの文言は報告本文と矛盾させない。実データで確認できたことと、仕組みの説明を書き分ける
5. 人の発言や仕様書を引くときは、画像内ではリンクにできないので、出典(コメント ID・仕様書のセルなど)を画像の説明文に置く

### ステップA2: 撮影

```json
{
  "label": "ISSUE-123", "baseUrl": "http://localhost:3000", "outDir": "<tmp>/annot", "port": 9341, "video": false,
  "viewport": { "width": 1600, "height": 1000 },
  "pages": [
    {
      "name": "01_master",
      "url": "/admin/terms",
      "actions": [ { "fill": ["input[name=year]", "2023"] }, { "click": "button.search" }, { "waitText": "2023/01/10" } ],
      "clip": ["table"],
      "annotate": [
        { "target": "table tr", "text": "第1期", "color": "red", "note": "<b>第1期</b>：年度の先頭", "x": 900, "width": 340 }
      ],
      "notes": [
        { "html": "<div style='color:#d32f2f'>■ 現状</div>第4期の次が翌年度の第1期になる", "color": "red", "width": 700 },
        { "html": "<div style='color:#2e7d32'>■ 期待値</div>第4期を年度の最後に置く", "color": "green", "width": 600 }
      ]
    },
    {
      "name": "02_csv",
      "url": "file:///<tmp>/annot/export.html",
      "clip": ["#csv"],
      "annotate": [ { "target": "#mark-1", "color": "red", "fill": false, "note": "G〜P列を削除", "pos": "below", "width": 600 } ]
    }
  ]
}
```

- `annotate.target` は CSS セレクタ。表の行は `"target": "table tr", "text": "<セルの文字>"` で特定する
- `pos` は right(既定)/ left / below / above。横長の対象(表の行)は `x` で吹き出しの左位置を指定し、空いている列に置く
- 注釈の対象が見つからないとエラーで止まる(セレクタや待ち条件を見直す)
- 枠と吹き出しの対応が分かりにくいときは `"numbered": true`、対象以外を暗くしたいときは `"spotlight": true`
- CSV は `node <skill>/scripts/csv2html.js export.csv <tmp>/annot/export.html --mark G-P:red` で表にしてから撮る

**全画像を Read ツールで目視確認する**。枠の位置・吹き出しの重なり・文字の切れがあれば config を直して撮り直す。

## トラブルシューティング

| 症状 | 対応 |
|------|------|
| `Chrome が見つかりません` | 環境変数 `CHROME_PATH` に chrome の実行ファイルを指定する |
| `録画用の ffmpeg がありません` | エラーに表示されたコマンド(`node <playwright-core>/cli.js install ffmpeg`)を実行する。ユーザーキャッシュ(`ms-playwright`)に入り、システム全体には影響しない |
| `playwright-core が見つかりません` | `npx -y @playwright/mcp@latest --help` を一度実行するか、`npm i -D playwright-core` |
| `Chrome に接続できません(port ...)` | 前回の Chrome が残っている。別の `port` を使うか、残っている Chrome を終了する |
| ログイン後の遷移でタイムアウト | `login.actions` のセレクタ、`waitUrlNot` を実画面に合わせて直す。ボタンが入力後に活性化する画面は `{ "blur": ... }` と `{ "waitEnabled": ... }` を挟む |
| `注釈の対象が見つかりません` | セレクタ・`waitFor`・`actions` を見直す。空の要素(修正前の「空欄」)は `waitFor` で存在だけを待てばよい |
| 帯が対象の下に出る(スクショ) | 対象がページ最上部にあり上に余白がないため(仕様)。そのままでよい |
| 動画で帯が下端に出る | 上端の帯が対象(注釈・前提・操作する場所)を隠すため、自動で移した(仕様)。上に固定したいときは `"bannerPos": "top"` |
| 証明書エラー | `ignoreHTTPSErrors`(既定 true)で自己署名証明書は通るので通常は出ない。`false` にしていないか、`baseUrl` のスキーム(http/https)を確認する |
| `環境変数 XXX が設定されていません` | config の `"${env:XXX}"` に対応する環境変数を付けて実行する |
| `GitHub に未ログインです` / `ログインが切れています` | ログイン状態は専用プロファイルに残り、セッションは約 2 週間(使うたびに延びる)。`github-attach.js check` で状態と期限を見られる。`upload` は切れていればその場でログイン用の Chrome を開いて待つので、`upload` をバックグラウンドで実行し、開いた Chrome で GitHub にログインしてもらう(待ちは 10 分) |
| `アップロードが完了しませんでした`(動画) | GitHub の動画サイズ上限(無料プラン 10MB)を超えている可能性。`hold` を短くするか画面数を減らして撮り直す |
| 動画の中身を確認したい | `video-sheet.js` で一覧画像にする。Chrome の `<video>` で `currentTime` を飛ばして撮る方法は、headless では最初のコマのまま変わらないことがあるので使わない。Playwright 同梱の ffmpeg は fps / tile などのフィルタが無いが、`-ss <秒> -frames:v 1 x.png` で 1 コマずつは書き出せる(webm のみ。H.264 の mp4 は読めない) |
| 動画がほとんど読み込み中の画面 / 本題が映っていない | 読み込みを待つ操作に `"cut": true` を付けて待ちを詰める(または `url` で開く)。変わる要素がビューポートの外にあるときは `viewport` を広げる |
| 修正前の「数秒かかる」が動画で短く見える | スクショや `cut` で録画を止めた区間が詰まっている。時間が論点の修正なら、`timer` で実際の時間を画面に出して測る(上記「見せ方」) |
| 枠・吹き出しが出てすぐ暗転する / 文字が読めない | `hold` を短くしている。スクショのタイミングのためなら `hold` ではなく `shotAt` を使う。capture.js は読める長さより短い `hold` を延ばす |
| 枠の中が空(スナックバーなどが消えた後) | 自動で消える表示。`{ "hover": "<その要素>" }` を最後の操作にして消えないようにする |

## 注意事項

- このスキルは撮影と検証だけを行い、コードの修正は行わない
- テストアカウントは開発環境専用のものを使う。本番環境・本番アカウントでは撮らない
- 証跡・config はリポジトリにコミットしない。パスワードは config に書かず環境変数で渡す
- `github-attach.js` の専用プロファイルには GitHub のログイン状態(セッション Cookie)が入る。共有しない・リポジトリに置かない
- 確認できた事実(表示内容)と推測を区別して報告する
